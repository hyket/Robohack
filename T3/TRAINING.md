# Дообучение Go1 для T3

`T3/train.sh` подготавливает окружение, загружает закреплённую версию Walk These Ways и исходный чекпойнт, применяет наш патч, запускает PPO на GPU и экспортирует новые веса для Participant. Первый запуск по умолчанию выполняет две итерации на 1024 параллельных средах. На RTX 3060 с 12 ГБ это разумный старт. Авторы указывают около 12 ГБ для 4000 сред. [Конфигурация Walk These Ways](https://github.com/Improbable-AI/walk-these-ways/blob/0e7236bdc81ce855cbe3d70345a7899452bdeb1c/README.md#training-and-logging)

## 1. Подготовить Windows-ПК

На Windows с драйвером NVIDIA можно начать с Ubuntu 20.04 в WSL 2. Один раз открой PowerShell от администратора и установи дистрибутив, если его ещё нет.

```powershell
wsl --install -d Ubuntu-20.04
wsl -l -v
```

Дальше команды выполняются в терминале Ubuntu. На обычной Ubuntu 20.04 x86-64 начни сразу с этого шага. `nvidia-smi` должен показать видеокарту. В WSL драйвер ставится в Windows. Работу самого Isaac Gym проверит пробное обучение. Если он не создаёт симуляцию в WSL, используй нативную Ubuntu 20.04 с NVIDIA. [Установка WSL](https://learn.microsoft.com/en-us/windows/wsl/install) · [CUDA в WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html) · [Совместимость Isaac Gym с WSL](https://forums.developer.nvidia.com/t/wsl2-and-isaac-gym-problem/192069)

```bash
nvidia-smi
sudo apt-get update
sudo apt-get install -y git python3.8 python3.8-venv python3.8-dev libpython3.8 \
  build-essential ninja-build libcurl4-openssl-dev libssl-dev libvulkan1 libgl1
```

Перенеси актуальный Robohack в Ubuntu, например в `~/Robohack`. В архиве NVIDIA прими условия и скачай **Isaac Gym Preview 4**. Скрипт принимает скачанный `tar.gz` или распакованный каталог `isaacgym`. [Архив NVIDIA](https://developer.nvidia.com/isaac-gym/download)

## 2. Запустить обучение

Из корня Robohack подставь путь к своему архиву. В WSL файлы из Windows обычно доступны в `/mnt/c/Users/<имя>/Downloads/`.

```bash
bash T3/train.sh --isaac-gym /path/to/IsaacGym_Preview_4_Package.tar.gz
```

Дождись строки `Participant weights:`. Она означает, что PPO завершился, чекпойнты сохранены и NumPy-экспорт сверился с TorchScript. Для оценки времени запусти 10 итераций с тем же числом сред, которое планируешь использовать дальше.

```bash
bash T3/train.sh --iterations 10 --envs 1024
```

В `training.log` видно время каждой итерации. Для оценки возьми медиану по итерациям с третьей и умножь её на нужное число итераций. Отдельно оставь время на старт, сохранение чекпойнтов, экспорт и проверку в MuJoCo. Например, если одна итерация занимает 3 секунды, 100 итераций займут около 5 минут работы цикла PPO. Для первого эксперимента на той же машине используй уже подготовленное окружение.

```bash
bash T3/train.sh --iterations 100 --envs 1024 --seed 42
```

Если пробный запуск упирается в видеопамять, попробуй `--envs 512` и измерь время заново. Если первый чекпойнт проходит проверку и хватает времени, запусти эксперимент на 400 итераций. `bash T3/train.sh --help` показывает все параметры, включая `--learning-rate` и старт с собственного `ac_weights_last.pt`.

Каждый запуск пишет в отдельный `output/t3-training/run-*`. В папке лежат `training.log`, настройки и метрики, патч, версии зависимостей, начальная и итоговая контрольные суммы. `checkpoints/ac_weights_last.pt` подходит для следующего этапа PPO. `walk_these_ways.npz` подходит для нашего Participant. Сохрани папку целиком для подтверждения обучения.

### Метрики и Weights & Biases

При прямом запуске в терминале прогресс обновляется в одной строке. В ней видны номер итерации, секунды на итерацию, средняя награда и RMSE скорости вперёд в м/с. Чтобы вывести весь журнал в терминал, добавь `--verbose`. При перенаправлении обоих потоков вывода в файл или `tee` скрипт также пишет обычный построчный журнал. Полный вывод тренера в любом режиме сохраняется в `training.log`.

В `metrics.jsonl` добавляется строка после каждой итерации. Там есть время сбора данных и обновления сети, общая пропускная способность в шагах среды в секунду, награда, ошибка отслеживания скорости, значения функций потерь и learning rate. В MuJoCo сравнивай число успешных эпизодов и время до 3 м.

С флагом `--wandb` те же показатели записываются в локальный офлайн-прогон W&B в папке `wandb` внутри эксперимента. Загрузка в аккаунт выполняется отдельной командой `wandb sync`, когда ты решишь её запустить. [Справка W&B об офлайн-режиме](https://docs.wandb.ai/support) · [Команда `wandb sync`](https://github.com/wandb/wandb/blob/v0.18.7/wandb/cli/cli.py#L399)

```bash
bash T3/train.sh --iterations 100 --envs 1024 --wandb
```

В каждой итерации PPO собирает 24 шага на среду, затем проходит по собранным данным 5 эпох с 4 мини-батчами в каждой. В следующей итерации данные собираются заново. По умолчанию learning rate PPO равен `1e-4`. Например, `--learning-rate 5e-5` уменьшает шаг PPO, а learning rate отдельного оптимизатора модуля адаптации остаётся `1e-4`.

### Пакет экспериментов на ночь

После успешного короткого прогона запусти пакет в том же окружении WSL 2 или Linux:

```bash
bash T3/train_night.sh --hours 8
```

Скрипт проводит до восьми последовательных этапов с лимитом по времени. Три ветки начинают с последнего проверенного прогона на 400 итераций в `output/t3-training` и используют PPO learning rate `5e-5`, `1e-4` и `2.5e-5`. Четвёртая ветка начинает с опубликованных весов Walk These Ways и другого seed. У каждой ветки два этапа. Второй этап берёт веса завершённого первого этапа и создаёт свежий оптимизатор. Если первый этап прервался, второй стартует с исходных весов своей ветки. Можно указать свою стартовую модель через `--checkpoint`.

Число итераций рассчитывается по оставшемуся времени и измеренной скорости. Каждый завершённый этап сохраняет отдельный экспорт для проверки. Путь к новой папке `night-*` печатается перед стартом и в конце. Сохрани её целиком вместе с предыдущими прогонами, чтобы остались исходные веса продолжений и журналы.

## 3. Как устроен патч

[Патч Walk These Ways](training/walk-these-ways.patch) применяется к коммиту `0e7236bdc81ce855cbe3d70345a7899452bdeb1c`. `Runner` загружает локальный `ac_weights_last.pt` и начинает новый цикл PPO со свежим оптимизатором. Тренировка идёт без камеры и окна. Среда задаёт движение вперёд в диапазоне 0,1–0,6 м/с с нулевой боковой скоростью и поворотом. Она использует рысь, коэффициенты позиционного управления Participant и ограничивает изменение углов каждые 10 мс. Формат наблюдений и выходов совместим с CPU-адаптером. [Код адаптера](policy.py) · [Конвертер весов](checkpoints/convert.py)

Качество готовых весов измеряй в публичном MuJoCo с реальным Safety Block. Сценарии и шкалы Isaac Gym и MuJoCo отличаются, поэтому итоговый выбор делай по зачётным прогонам.

## 4. Собрать образ и сравнить

Этот шаг можно выполнить на Mac с Docker в Lima. Перенеси папку эксперимента из Ubuntu на машину, где запускается MuJoCo. Укажи её скрипту сборки. Он проверяет контрольные суммы, собирает отдельный образ и запускает `ping` без сети.

```bash
bash T3/build_trained.sh /path/to/run-YYYYMMDD-HHMMSS
```

Сравни `go1-participant:t3` и `go1-participant:t3-trained` на одинаковых настройках публичного симулятора. Пример ниже использует ранее собранный локальный образ симулятора. Заменить его можно по [инструкции запуска T3](README.md).

```bash
sim_dir=$(find "$PWD/T3" -maxdepth 1 -type d -name 'go1-simulator-public-*' -print -quit)
python3 T3/demo.py series "$sim_dir/run_local.py" \
  --sim-image robohack-t2-sim-source:local --participant-image go1-participant:t3-trained \
  --speed 0.6 --count 10 --output output/t3-trained-evaluation
```

Исходная модель прошла 10 из 10 локальных прогонов при 0,6 м/с. В отдельной проверке на Mac один эпизод с этой командой занимал около 15 секунд по часам, включая пересоздание контейнеров при уже запущенной Lima. При выборе смотри на успешные эпизоды, падения и время достижения 3 м после прогрева. Для подтверждения дообучения передай организаторам веса, конфигурацию, журнал и результаты. [Исходная серия](../output/t3-results.json) · [Сравнение скоростей](../output/t3-speed-sweep.json) · [Требования T3](../Docs/HACKATHON.md#source-4)

Для сравнения всех кандидатов из новой и предыдущей папок используй `T3/evaluate_night.sh` в окружении, где уже работает локальный MuJoCo через Docker:

```bash
bash T3/evaluate_night.sh --count 3 /path/to/new-night /path/to/previous-night
bash T3/evaluate_night.sh --count 10 /path/to/finalist-run /path/to/other-finalist-run
```

Первая команда даёт быстрый отбор. Во вторую подставь пути к 2–3 лучшим прогонам из таблицы результатов. При необходимости укажи `--launcher` и `--sim-image`. Итоги, контрольные суммы использованных весов и записи эпизодов лежат в `output/t3-training/evaluation-*`. Больше успешных эпизодов важнее времени. При равном числе успехов скрипт сравнивает медианное время до 3 м.

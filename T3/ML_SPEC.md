# ТЗ по ML и RL для Т3

**Твоя задача — подключить политику ходьбы Go1.** На каждом шаге она получает измеренное состояние робота и заданную скорость корпуса. На выходе нужны 12 целевых углов суставов. Первый результат — повторяемый инференс на CPU на одном записанном кадре. Затем подключаем политику к симулятору и добиваемся 3 м вперёд без падения.

## Как работает один шаг

```text
LowState + заданная скорость
  → подготовка наблюдения и его истории
  → инференс политики
  → перевод действий в 12 целевых углов
  → ROS 2 публикует LowCmd в /lowcmd_bare
  → Safety Block Т2 проверяет цель и публикует /lowcmd
  → MuJoCo применяет команду и выдаёт следующий LowState
```

Заданная скорость `0.3` означает «корпус должен двигаться вперёд со скоростью 0,3 м/с». Политика по IMU и суставам выбирает, как двигать ногами. Целевой угол `q_des` задаёт, куда повернуть сустав. Позиционный регулятор симулятора использует `kp` и `kd`, чтобы по ошибке угла и скорости вычислить момент. Следующее наблюдение отражает то, что реально произошло после проверки Т2. [Контракт Т3](../Docs/HACKATHON.md#source-4) · [Safety Block](../T2/t2_checked/safety_block.py)

## Граница твоей ответственности

| Твоя ML/RL-часть | Сторона ROS 2 и интеграции |
| --- | --- |
| Выбор весов, точная сборка наблюдения, история и её сброс между эпизодами | Приём `/lowstate`, `/cmd_vel` и `/clock`, вызов модели с нужным периодом |
| CPU-инференс, преобразование действий в целевые углы, порядок суставов и параметры позиционного управления из конфигурации модели | Упаковка целей в `LowCmd` с `mode = 0x0A`, публикация в `/lowcmd_bare`, запуск Safety Block |
| Сравнение моделей, диагностика поведения и выбор скорости для сдачи | Запуск контейнера в режиме `T3`, сбор журналов, перенос скорости в `preferred_speed_mps` |

Первый модуль можно сделать на Python с обычными массивами. Удобный интерфейс — `reset()` и `step(state, command, sim_time_s)`. Результат `step` содержит `q_des[12]` в радианах. Для интеграции отдельно передай период политики, значения `kp` и `kd` и правила для `dq` и `tau`. Нулевые `dq` и `tau` подходят, если так устроен исходный контроллер политики.

## Что реально приходит от Go1

| Данные | Форма и смысл |
| --- | --- |
| `motor_state[:12].q` | 12 измеренных углов, рад |
| `motor_state[:12].dq` | 12 измеренных скоростей суставов, рад/с |
| `imu_state.quaternion`, `imu_state.gyroscope` | Ориентация `[w, x, y, z]` и угловая скорость, рад/с |
| `imu_state.accelerometer`, `foot_force` | Дополнительные поля, если их ожидает политика |
| `/cmd_vel` | `[vx, vy, yaw_rate]` в м/с, м/с и рад/с |
| `/clock` | Время симуляции для выбора момента следующего шага |

Порядок в Unitree — **FR, FL, RR, RL**, внутри ноги **hip, thigh, calf**. Измеренная линейная скорость корпуса в `LowState` отдельным полем отсутствует. Если кандидат требует её для инференса, понадобится оценка по доступным сигналам или другой чекпойнт. `/odom/ground_truth` публичного симулятора используй для внешнего замера движения. [Тип LowState](../T2/t2_checked/vendor/unitree_go/msg/LowState.msg) · [Порядок суставов в гайде](README.md)

## Что делать по порядку

### 1. Разобрать готовую модель и получить 12 чисел

Кандидат для первого эксперимента — **Walk These Ways** для Go1. У авторов есть конфигурация `parameters.pkl` и два TorchScript-файла. В их примере история наблюдений сначала проходит через `adaptation_module_latest.jit`. Полученный вектор объединяется с историей, и `body_latest.jit` выдаёт действие. Совместимость с нашим MuJoCo предстоит проверить прогоном. [Опубликованный эксперимент](https://github.com/Improbable-AI/walk-these-ways/tree/master/runs/gait-conditioned-agility/pretrain-v0/train/025417.456545) · [Код инференса](https://github.com/Improbable-AI/walk-these-ways/blob/master/go1_gym_deploy/scripts/deploy_policy.py#L52-L63)

1. Из конфигурации и исходного кода выпиши состав и размер одного наблюдения, длину истории, нормализацию, период шага, параметры походки и формулу декодирования действия. Для дополнительных параметров, например частоты шага, начни с пресета из исходной реализации. Команда судьи задаёт три компоненты скорости. [Подготовка наблюдений и действий](https://github.com/Improbable-AI/walk-these-ways/blob/master/go1_gym_deploy/envs/lcm_agent.py#L114-L186) · [История наблюдений](https://github.com/Improbable-AI/walk-these-ways/blob/master/go1_gym_deploy/envs/history_wrapper.py)
2. **Проверь перестановку.** В Walk These Ways порядок **FL, FR, RL, RR**. Для его входа переставь блоки из формата Unitree по индексам `[1, 0, 3, 2]`, каждый по три сустава. Для выхода используй ту же перестановку в обратную сторону. Например, `FR_hip` переходит из индекса 0 в индекс 3 и после инференса возвращается в индекс 0. Сделай тест с разными значениями для всех 12 суставов. [Перестановка у авторов](https://github.com/Improbable-AI/walk-these-ways/blob/master/go1_gym_deploy/utils/cheetah_state_estimator.py#L47-L52)
3. На CPU прогони записанное состояние с фиксированной командой и одинаковым сбросом истории. Для позиционной политики такого типа цель получается из базовой позы плюс масштабированное действие. У Walk These Ways есть отдельный масштаб для `hip`. Сверь наблюдение и выход с исходным кодом на тех же данных. Результат — 12 конечных целевых углов в порядке Unitree и воспроизводимый тест преобразований. [Декодирование действия](https://github.com/Improbable-AI/walk-these-ways/blob/master/go1_gym_deploy/envs/lcm_agent.py#L171-L186)

### 2. Проверить первые шаги в MuJoCo

Сначала добейся устойчивого запуска из стойки. Потом подай `vx = 0.3` м/с. Записывай рядом желаемую скорость, `q_des` политики, фактический `q` из `/lowstate`, а также цели до и после Safety Block. С измеренного состояния начинается каждый следующий инференс.

- Если цели политики меняются, а `/lowcmd` держит одну позу, посмотри причину отказа Т2 и разность с **последней опубликованной** целью. Лимит перехода — 5° на сустав. Проверь стартовую позу, масштаб действия и период инференса.
- Если команды проходят, а робот падает, начни с порядка суставов, ориентации IMU, нормализации, истории и `kp`/`kd`.
- Замерь время подготовки входа и инференса на CPU. Сравни его с периодом модели. Частота инференса определяется её конфигурацией. Норма **≥50 Гц за 5 секунд**, разрыв **≤100 мс** относится к выходу Safety Block `/lowcmd`. [Запуск симулятора](README.md#2-первый-запуск-на-mac) · [Критерии Т2](../Docs/HACKATHON.md#source-3)

### 3. Зафиксировать результат и решить, нужно ли дообучение

Первый зачётный ориентир — один эпизод на **3 м вперёд без падения**. Дальше доведи до **7 из 10** локальных эпизодов. На серию выбирай одну скорость в диапазоне **0,1–0,6 м/с**. Каждый эпизод начинается с нового состояния политики и симулятора. После **1,5 с** прогрева есть до **90 с** симуляционного времени на движение. Измеряй смещение по исходному направлению, время до 3 м, факт падения и количество отклонённых целей.

Готовая политика может дать до **15 баллов** за ходьбу. Если базовый вариант уже воспроизводимо работает, следующим этапом можно дообучать его на похожей физике с учётом Safety Block. Для дополнительных **15 баллов** нужны хотя бы один успешный эпизод, веса, конфигурация обучения и журналы с результатами. [Правила испытания и баллы](../Docs/HACKATHON.md#source-4)

## Что передать на интеграцию

- Версию чекпойнта и конфигурацию с периодом, порядком суставов, масштабами, позой по умолчанию и параметрами регулятора.
- CPU-модуль инференса и пример запуска на одном кадре с ожидаемым выходом либо численным сравнением с оригинальной реализацией.
- Журнал проверочных эпизодов и выбранную скорость. В итоговом Participant веса и зависимости должны быть доступны без сети.
